# 静态产物交付规范

给用户的"看的东西"一律走文件交付：不发布、不部署、不起服务。网页/图片点开附件即可查看（网页完整可交互），Office/PDF 等下载后打开。

## 通用规则

1. **自包含**：单个文件打开即可完整使用；多文件产出打成一个 zip（命名带日期）。
2. **命名**：描述性中文名 + 日期，如 `部门周报-0902.html`、`试点名单-0902.xlsx`。
3. **交付路径**（按会话类型，选对一条）：
   - 一对一（私聊）：`cp 产物路径 "$AGENT_OUTBOX/"`，回合结束自动作为附件出现在聊天里。
   - 群 / 频道：把文件写在普通工作区路径（如 `work/报告.html`），发消息时在 post 的 `files` 参数里带上该路径。**群里 outbox 不生效**。
4. **回复话术**：文件名 + 一行内容概要 + 查看方式——网页/图片说"点开即可查看"，Word/PPT/Excel/PDF 说"下载后用 Office/WPS 打开"，.drawio 说"下载后用 draw.io 打开"。不要把文件内容整段贴进回复。
5. **交付前校验**：`ls -la` 确认文件存在、大小正常（HTML/文档明显小于常见下限多为空壳）。
6. **边界**：不向用户提及 outbox、管道、路径细节；不主动提议"发布成应用/部署成服务"。用户明确要"在线可访问的服务"时：有可用的部署技能就用它，没有就说明该通道后续恢复。要把文件**持久**共享给不在当前会话的人，用 `write` 的 `share`，并在回复里说明它会出现在对方「文件」页。

## 分类型要点

| 类型       | 要求                                                                                                                                                                                                                                                                                                                                               |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 网页 .html | 脚本/逻辑依赖零外链：`<script>`、`<iframe>`、`<video>/<source>` 的 src 一律内联或去除——用户多在内网/国内网络，CDN 加载失败即功能损坏。字体/图标允许外链但必须带系统回退，断网打开仍要可用。图片内联（base64）。交付页运行在无同源沙箱里：**禁用** localStorage、sessionStorage、cookie、相对路径 fetch/XHR（会直接白屏）；交互全部用纯前端 JS 实现 |
| 图片       | PNG / JPG（聊天里直接出缩略图）；矢量图示可用 SVG                                                                                                                                                                                                                                                                                                  |
| Office     | .docx / .pptx / .xlsx，生成方法见 office-docs 与 ppt-master；交付后下载打开                                                                                                                                                                                                                                                                        |
| .drawio    | 交付后用桌面 draw.io / diagrams.net / WPS 打开，可继续编辑                                                                                                                                                                                                                                                                                         |
| 数据表     | 给 Excel/WPS 用户优先 .xlsx；出 .csv 且含中文时必须带 UTF-8 BOM——python 写文件用 `open(path, "w", encoding="utf-8-sig")`，否则中文打开乱码                                                                                                                                                                                                         |
| PDF        | 由 HTML 经浏览器打印或库生成，按普通文件交付                                                                                                                                                                                                                                                                                                       |

## 能力映射

架构图、流程图、拓扑 → 可用的图表技能（如 drawio）；演示页 → 可用的幻灯片技能（如 frontend-slides）；图片 → image-gen；Word/PPT/Excel → office-docs / ppt-master。生成之后，回到本规范交付。

## 校验点

- `ls -la "$AGENT_OUTBOX/"`（群场景则确认 post `files` 的路径真实存在）。
- HTML 交付前：`grep -En '<(script|iframe|video|source|embed)[^>]+(src|data)=.?https?:|@import|url\(.?https?:' 产物.html` 应无输出（抓脚本/框架/媒体外链与 CSS 内的外链引用——这些加载失败页面就坏；字体 `<link>` 允许，但需确认有系统字体回退）。
